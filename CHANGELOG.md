## [1.3.0] — 2026-07-27

The machine gets a checklist it can be held to, and its front door is prose rather
than code — because on a new machine there is no checkout to run a checker from.
`scripts/lib/toolchain.mjs` is the one place a tool or an install string is named,
`check-machine.mjs` reports the machine against it, and a test fails when the guide
and the manifest drift apart. Copilot leaves in the same release it was going to be
justified by: the allowance is metered rather than flat, and the review half is
refused outright on a private repo on the free plan.

### Added

- **`/continuum`** — the half of a chat-to-chat transition that was still hand-work. `/handoff` writes the note; nothing wrote the *prompt*, and nothing checked that what it printed was complete. The mechanism is not a better template: `skills/continuum/scripts/validate-prompt.mjs` is a pure, deterministic, dependency-free `validate(promptText, context)` that **refuses an invalid prompt before it reaches disk**, over six fixed sections and fifteen rules. The rule that closes the real hole is `branch-mismatch`: the prompt must name the branch actually checked out, compared against git rather than asserted, with **no escape hatch** — naming where the work sits is never wrong, and omitting it is how a fresh session silently branches from `main` and loses the plan. `branch-unknown` catches the other half, a stale or typo'd branch the prompt tells the next chat to *continue* on. It carries the one heuristic in the file and it fails closed: a create-directive needs an **imperative** reading, so "do not create a new branch; stay on `x`" and "scope was cut on `x`" license nothing, and only candidates *after* the verb are exempt. One silent pass remains and is named in the source rather than discovered later — a typo'd base on a genuine create line, because a `cut … from …` line puts the base and the new branch in the same position and nothing in a pure function can tell them apart. Git state arrives as `context`; the validator makes no git call, no fs read, no clock call of its own, and `node:*` is the whole import list. **Ratified by two `/deliberate` panels.** The first refused role-checking 3–0, the proposing seat reversing itself: the skill supplies those labels, so the validator would be grading its own homework. Only the one *fact* survived, `manifest-contract-first`. It also lowered the manifest floor to **one entry**, because a greenfield first phase has no precedent, no constraining test and no shared dependency, and a higher floor refuses a legitimate manifest by construction. The second panel split a question the spec had fused: `constraints-empty` is the right rule (3–0) *and* adding it is a scope increase past a ratified fifteen (3–0), since only a contract table ever carried the requirement while the Rules table, acceptance criteria and testing plan all omitted it — calling that always-normative afterwards is retroactive process laundering. So the rule is **pre-decided behind a revisit trigger** rather than shipped or dropped: the first empty `## Constraints` that costs somebody a re-introduced correction adopts it without another panel. What the gate deliberately does *not* do is rule on whether the constraints are the binding ones or the risks the real ones — those are judgements, and a validator certifying them would be doing what `/crit` was built to stop. `/handoff` gives up the clearing trigger in the same change, because the router picks on the description line and two skills claiming "I'm going to clear" leave it no way to choose; a test asserts both halves, since a split narrowed on one side is still the collision. **Dogfooded on its own build**, which cost it two defects no test could have caught: §1 gave three branches for delegating to `/handoff` and none was the case that arose — the note was already written and committed, so following it literally records one transition twice — and §2 refreshes a stale code map while §3 demands a clean tree, with nothing saying to commit the map, so the honest reading was to disclose your own side effect as a risk. The run also produced a prompt that **passed `validate()` on the first attempt**. Two defects were found earlier by review rather than by tests, and both are worth naming: the skill's own §5 template omitted `## Constraints`, so an agent copying it generated a prompt its own validator refused — the test meant to catch that passed because the word appears in neighbouring prose, and a test now extracts the template, fills it and runs the gate on it; and the CLI treated `--branch` as optional and printed `clean` for a wrong-branch prompt, reporting the exact failure the skill exists to prevent as success. 82 tests across `tests/continuum-prompt.test.mjs` and `tests/continuum-skill.test.mjs`, plus a vendored exemplar (suite → 539).
- **`skills/continuum` ships in the daftkit export**, and a flip condition rather than a judgement call decided when. Three of the plan's four clauses held at C3: the generated prompt validated on the first attempt, the suite and `verify-templates` were green, and the daftkit standalone test passed with the entry removed. The fourth could not be self-satisfied — the session that *wrote* a prompt cannot be the session that proves one works — so the export was held. It came off on 2026-07-26, when a fresh session executed a generated prompt end to end and landed this branch without asking a question the prompt should have answered. The condition refusing the author's own run as its own evidence is what made the second run mean something. The run recorded one defect against the prompt: it asserted the CHANGELOG needed no edit while also licensing the flip that falsifies this very bullet — a prompt may not pre-declare a file untouched when it authorizes work that changes it. Its two test files are separately held from the **daftplate** export for the structural reason tracked in issue #54: that export ships `tests/` but not `skills/`, so any test for a bundled skill script arrives importing a module that is not there. The guard caught it both times, but its remedy has now been hand-written four times and the denylist has grown from three entries to eight without anyone deciding it should.
- **`/deliberate` now records the panel.** A new step 8 writes `docs/panels/YYYY-MM-DD-slug.md` and commits it. The skill was spending six figures of tokens and leaving nothing behind but a chat message, so the same question was reopenable in six weeks at full price. The record's reusable half is not the argument but the **revisit triggers**: every seat is already asked what would move it, and those answers are falsifiers rather than opinions — tabled against what each one reopens, with a column for dated observations, and a rule that a row reopens on logged evidence and never on a hunch. A run that went *well* counts as evidence too; a row collecting only failures is measuring the wrong thing. The record also names **what moved and why**, because a seat reversing itself — or a case the chair injected that moved two seats — is the evidence that the round was worth its cost, and a round where nothing moved is the argument for one fewer round next time. Two tests hold it: the skill must name the destination and the falsifier framing as a numbered step, and every record in `docs/panels/` must carry both sections (suite → 457).
- The first record, `docs/panels/2026-07-25-continuum-selection-criteria.md`, covers the two-round panel that settled `/continuum`'s selection criteria, validator floor and failure vocabulary. Four positions moved, including a seat withdrawing its own proposal once it saw that the skill would be supplying the labels its check validated. It also logs a process finding against the skill itself: round 2 cost *more* than round 1 (61,894 against 53,747) despite being a targeted dispute round rather than a re-file, because the round-1 transcripts are carried in whole as `others` — if that repeats, the dispute prompt should carry a summary instead.
- **The machine toolchain is one manifest, and its front door is prose.** What a machine of yours needs was scattered across a four-entry `PREREQUISITES` array in `scripts/setup-repo.mjs`, a `docs/setup-guide.md` table that had already drifted from it, and — for everything past those four — nothing at all. `scripts/lib/toolchain.mjs` is now the single source of truth and the only place an install string is written; it is `.mjs` rather than `.json` so the tier rationale lives beside the entry it justifies. **`tier` means "a machine of yours is misconfigured without it", not "a script breaks"**, a distinction forced by `restic` being `required` for having nothing back up what matters — a definition keyed on script breakage would have filed it next to `fzf`. The narrower fact is `blocksScripts`, which is what `setup-repo.mjs` filters on, so repo bootstrap still checks exactly the four tools it checked before the file existed, now asserted by value rather than maintained by hand. An `installer` discriminator (`winget` | `npm` | `gh-extension`) maps to a table of required install-string prefixes, because an earlier draft of the design asserted every `install` begins `winget install ` and that was false for three entries; a new installer now means adding a rule, which is visible, rather than loosening the check for everyone. There is deliberately **no `license` field**, refused by the validator rather than by convention: a public repo asserting licence facts about third-party projects — presence-checked here, correctness-checked nowhere — is an unverified public claim that no test catches and no user reports, so `url` credits upstream and lets it be the authority on itself. Requiring every `url`, `author` and install id to be verified against upstream and the registry rather than written from recall paid for itself immediately, and against the *design* rather than an implementer: **`gh copilot` is archived upstream** (`archived: true`, last push 2025-10-30) and its successor is a standalone npm CLI, so that entry followed the product rather than shipping a dead install string — and was then dropped outright with the rest of the Copilot surface, see the bullet above. The same pass found `rg` annotated "already present" on a machine that does not have it, Claude Code's bundled ripgrep being the likely source of the belief. **`scripts/check-machine.mjs`** reports the machine against that manifest as the second pass, its report logic pure and driven by an injected prober so the whole thing is assertable without touching `PATH` or capturing stdout. It groups by tier and expands only what is **absent** — twelve entries times four lines would bury the two that matter, so credit appears where a tool is actually being recommended to you — and exits non-zero **only** on a missing `required` tool, which is what makes it CI-safe. `--profile <name>` adds a profile's tools and a scaffolded repo's `.daftplate.json` supplies it automatically; `--json` carries the same verdict. It is stateless by construction — no snapshot, no ignore list, no adopt/ignore bookkeeping — because dismissals exist to quiet drift noise and drift is what the manifest removes. Extracting it exposed an import cycle, `setup-repo.mjs` importing the reporter that was importing `commandExists` back, which ESM tolerates for hoisted declarations and would therefore have broken silently the first time someone converted the function to a `const`; `commandExists` now lives in `scripts/lib/probe.mjs` and the old path re-exports it. **The no-write test falsified an acceptance criterion on its first run**, which is the best thing it could have done: the criterion said the checker "writes no file anywhere, creates no directory", and probing `gh --version` makes **gh** create `$XDG_STATE_HOME/gh` — isolated per variable, with `USERPROFILE`, `HOME` and `XDG_CONFIG_HOME` all staying clean. The probed tool writes, not the checker, so the criterion was reworded to "keeps no state of its own", which is what its own rationale always argued for; the test allowlists exactly `gh` with the reason inline rather than unsetting the one variable that reveals the write. **That the guide and not the checker is the primary interface** inverted the original proposal and was the review panel's central finding: on a **new machine**, the case the whole thing exists for, there is no checkout and no installed skills, because installing skills needs the repo cloned, which needs `git`, which is itself an entry on the list being checked. A page on github.com is the only interface that exists at that moment, and it was already in the public export. The guide leads with `git` and `node` for the same reason, states the `tier`/`blocksScripts` distinction rather than implying it, keeps profile-restricted tools in their own table so they inform without nagging, and hands over to `check-machine` at the end; its `## Agent surface` section gains the settled configuration, including **MCP servers: none** and the one-paragraph ADR any addition must supply. A **prose-matches-manifest test** makes drift a failure rather than a discovery, and building it found the hole in the criterion as written: asserting that each unrestricted entry's `name` appears is not enough, because deleting the entire `restic` row leaves the word `restic` in the neighbouring rationale and the assertion stays green — a test passing on prose adjacent to what it meant to check. The gate therefore also requires the verbatim `install` string, unique per entry, and word-bounds the name so `GitHub CLI` cannot stand in for `Git`; deleting a row was watched turning both red. Three refusals are recorded alongside: a `/doctor` skill (3–0 — ADR 0002 puts skills in daftkit and this manifest in daftplate, so sharing needs vendoring, a bug here), a toolchain check inside `/orient` (3–0, all seats reversing — it would run per session against machine state that changes monthly, against `/orient`'s own "under 30 lines, under 15k tokens" budget), and a `--drift` snapshot mode (3–0 — stale ignores accumulate until the tool itself is ignored, the failure it was meant to prevent). Suite 553 → 610.

### Fixed

- **The version probe is a per-tool fact, and assuming otherwise reported an installed tool as missing.** `commandExists` ran `<command> --version` for everything, which is right for eleven of the twelve manifest entries and wrong for `restic`: it exits 1 with `unknown flag: --version` and wants `restic version`. So `check-machine` called restic absent on a machine that had it, and since restic is the only `required` tool that was missing, **the machine could never pass** — and wiring the checker into CI would have failed the build for a tool that was installed. The defect was invisible for exactly as long as it took to install restic, which is the uncomfortable part: it shipped in T2, survived T3's review, and was found within a minute of the manifest's last unowned entry arriving on disk. Entries now carry an optional **`versionArgs`**, defaulting to `['--version']` and declared only where that default is wrong, because a default restated on every entry stops being a default and becomes twelve places to get it wrong; the validator holds its shape and a test asserts `restic` is the only entry declaring one, so a future addition is a visible decision rather than a quiet copy-paste. Both forms were **run against every installed tool** rather than reasoned about — `git`, `gh`, `node`, `gitleaks`, `codex`, `copilot` and `clasp` all answer `--version`, and `restic` alone does not. `rg`, `fzf`, `bw` and `wrangler` are absent from this machine and their probe form is therefore **unverified**, which is now stated rather than assumed: the same class of false negative is still possible for any of the four, and installing one is what would settle it. `tests/probe.test.mjs` is new and is deliberately the one file in the suite that touches `PATH`, because the argument list is the whole point and an injected prober would prove nothing about it — it pins the fallback and proves a bad argument list is the difference between present and absent, using the `node` the suite is already running inside. **Acceptance criterion 1 now holds live** for the first time rather than by unit test alone: with restic installed and the probe corrected, a machine missing only `recommended` tools prints them and exits **0**. Suite 610 → 618.

### Removed

- **Copilot is not part of this setup, and the plan that added it was withdrawn.** `setup-repo --remote` briefly enabled automatic Copilot code review as a repository ruleset. It was built, merged, and then removed in full on the day the claim underneath it was finally checked. Two things were wrong and they are worth separating. The **premise**: the audit called Copilot Pro "free with your setup", the design corrected that to "paid but flat-rate, therefore the cheapest token in the stack", and *both* are wrong — the allowance is **metered and exhaustible**, so nothing routed there is free at the margin and the entire quota-relief argument evaporates with it. The **mechanism**: Copilot review is delivered as a ruleset, and rulesets are **403 on a private repo on the free plan** — a gate this repo had already encoded as `PAID_PLANS` and then treated as incidental. Development happens in a private repo, so the Codex ceiling this was built to relieve sits in precisely the place the mechanism cannot reach; what remained was the public export repos, where the reviewed diff is a publication snapshot of already-reviewed, already-merged work with no path to act on a finding. Removed: the `copilot-code-review` entry in `remoteSettings()`, `COPILOT_RULESET_NAME`, `copilotRulesetBody`, `listRulesets`, `applyCopilotReview`, the `REMOTE_APPLIERS` dispatch map and its branch in `applyRemote`, 13 tests, and the `copilot` manifest entry with its row in `docs/setup-guide.md`. The **dispatchability guard stays**, retargeted at `REMOTE_CALLS`: it exists because a setting listed with no way to apply it once took four other settings down with it, and that reason is untouched by which settings happen to exist today. `--remote` still applies what GitHub accepts and still reports the rest as unavailable with a reason and an unblock. The M1 plan is kept at `docs/designs/2026-07-27-m1-copilot-code-review.md` with a **DROPPED** status rather than deleted, because the reasoning is reusable and the failure is the instructive part: **both defeating facts were checkable before a line was written** — the 403 was already in this repo's own gate, and the billing shape was one question away. A plan justified by a cost claim verifies the cost claim first, which is the install-string discipline applied one level up. Suite 618 → 605.

## [1.2.0] — 2026-07-25

Design review loses the ability to assert what it never looked at. `/crit` refuses
an appearance finding whose evidence does not exist — enforced by a validator and a
`Stop` hook rather than by prose, because the failure it was built against happened
*inside* an invoked skill. `/deliberate`, measured against a real 611k-token run and
rebuilt where the numbers said it was wasting money, now carries the same rule: see
the artifact rendered before ruling on how it looks.

### Added

- **`/crit`** — a design critique that cannot file a judgement it did not look at. The mechanism is not a better prompt: an **evidence manifest** must exist and validate before the review may report, and an appearance finding filed without the evidence that would have shown it is **refused**, not warned about. `skills/crit/scripts/manifest.mjs` is a pure, deterministic, dependency-free `validate(manifest, findings)` — no rendering, no finding; a comparative claim with no variants, no finding; an unstated `kind`, no finding, because the gate fails closed and relabelling an appearance claim as structural has to be typed deliberately. A rendering that will not name its **target** is likewise not a rendering, and a finding may cite the `evidence` it rests on and is refused if it cites an artifact nobody produced — both of those came out of dogfooding the skill on a real design system, where every appearance finding was admitted on the strength of a render whose artifacts were of a purpose-built harness rather than of the subject, and nothing in the gate noticed. Citation is offered rather than compelled: the validator cannot rule on whether a picture shows what a finding says it shows, and one that pretended to would be certifying a judgement. Findings that do not depend on perception — spec contradictions, accessibility violations, structural defects — pass through **untouched** and ship even when visual review is blocked, with the report stating plainly that it was. A `non-viewable` target is accepted only with a stated justification; a missing detector or owned check degrades the run and never refuses a finding. The skill itself is thin by design: two isolated assessments, the detector run, browser inspection and the degraded-banner convention all belong to `impeccable`'s `critique` playbook, which specifies them better, so `/crit` **references** that ownership and a test holds a denylist of doctrine only a copy would carry. The measured failure it was built against invoked `impeccable` as a *persona* and never loaded its playbook, then filed confident appearance judgements about something nobody had rendered. What `/crit` does own is the manifest and five checks that exist nowhere upstream: P0 preflight (stop rule, evidence plan, reversal cost, the five-axis triage shared with `/deliberate`), L1 derived identity — identity from the subject's own materials and vernacular, with `frontend-design`'s AI-default cluster list run against **your own proposal**, since the measured run diagnosed one cluster and converged on another from the same list without noticing — L2 layered taxonomy (name the colour story, type pairing and component grammar separately; accessibility outranks taste and is refused, not traded), P4 restraint (one signature move; anything past it trades rather than appends; the sum gets a named owner), and escalation to `/deliberate` only when a values conflict survives the evidence. Ratified by a two-round `/deliberate` panel that moved all three positions and produced the mechanism no seat proposed in round 1, then dogfooded on a frozen design system in another repo — which cost it two defects, both fixed test-first. The second: `SKILL.md` told the chair to write the manifest "in the repo under review" while the hook resolves that path against the **session** cwd, so a fully evidenced critique of any repo you were not sitting in would have blocked anyway. Both halves named the same relative path and disagreed silently about its root, which every existing test passed. 57 tests (suite → 455).
- The `/crit` gate is enforced from outside its own prose, because a skill cannot be its own sole control — the 611k-token failure happened *inside* an invoked skill and then diverged from it in six places. A **`Stop` hook** installed to `~/.claude/crit-report-gate.mjs` refuses to let a session that invoked `/crit` finish without a **complete** `.crit/evidence.json`. It is registered **user-level** by `install-skills.mjs` rather than shipped in `base/files/dot-claude/settings.json`, which only reaches *scaffolded* repos — design reviews happen in repos that never were, the same reach failure that killed the addendum proposal. The boundary is mechanical rather than promised: the hook calls `validateManifest`, not `validate`, so **findings are not in its input** and it cannot certify a judgement even by accident — L1/L2 conclusions are not machine-observable and a hook pretending otherwise would be worse than none. An absent skill produces silence; a present `SKILL.md` whose validator is gone claims a gate it cannot run and is blocked loudly. Registration only ever adds: an existing `Stop` hook keeps its place and contents, and a `settings.json` that will not parse is left byte-for-byte alone. Detecting the crit run **parses specific transcript fields** and never matches substrings, the fix for three successive attempts that each blocked the session that wrote them — `<command-name>/crit</command-name>` contains no character JSON escapes, so it survives verbatim inside an `Edit` argument, and a session that merely *develops* crit contains every marker. Every payload shape was read from `sdk.d.ts` and live transcripts rather than recollection, because `base/files/dot-claude/question-gate.mjs:21-26` records the alternative: a hook that unit-tested green against a field the binary never sends, and so never fired.

### Changed

- `/deliberate` was measured against a real run and rebuilt where the numbers said it was wasting money. A 611k-token art-direction panel on 2026-07-24 was retrospected, and the retrospective's own recommendations were then put through the skill as written — three real archetypes, `buildPrompt`, codex via stdin, one round — for 56,196 tokens, about a ninth, which found an error of fact, an internal contradiction and a blind spot in the draft. What that panel ratified is now in the skill. **Round 2 is a targeted dispute round, not a re-file**: the chair extracts the live disputes and each seat rules on those and nothing else via a new `buildTargetedPrompt`, and a response must change a conclusion or cite new evidence — the measured failure was a round 2 that cost *more* than round 1 (253,888 tokens against 250,724) with zero tool calls and about three new insights against eighteen. **A round is never triggered by agreement**, which proves a finding salient and never proves the panel complete — corroboration, not convergence — but by unresolved decision criteria and reversal cost, with two rounds the expected path and three still available. A **preflight** now precedes the first prompt: a five-axis entry test (reversal cost, commitment, reach, perceptual prominence, uncertainty — because a reversible choice repeated on every screen can harm more people than an obscure irreversible one), a **stop rule** naming what evidence would justify no change, and an **evidence plan** — *if the artifact is visual the panel must see it rendered*, at real sizes, in every theme, before the final dispute, since four of the five defects that survived the measured run are questions about what something looks like, decided by three design specialists reading CSS. Token forecasting is out; reporting the real cost afterwards stays. The **executor is now an explicit choice** — codex for independence, subagents when the panel must inspect an artifact that cannot be pasted — decided on artifact access, provenance and independence and **never on line count**, with the independence surrendered named in the cost report. Substituting the archetypes is allowed but must preserve *opposed claims tied to acceptance criteria* with one seat defending the status quo on the merits; a nominal "restraint" seat is called out as performative. `buildPrompt`'s terse format is mandated over any invented multi-section schema, which homogenises three traditions into three near-identical documents, and the skill states the principle so it survives the helper rotting. The closing `AskUserQuestion` narrows to **one question at approval altitude** — the run asked four where one was open — while keeping the rule that the panel advises and the owner decides. 2 more tests (suite → 388).
- The publish export is checked for **dangling imports**: no exported `.mjs` may reference a path the export does not also ship. Caught a real one — the three `diagram` test files were selected into the `daftplate` export while `skills/` is not (ADR 0002 puts skills in daftkit), so public daftplate would have received three test files importing a converter that is not there. The public repos have no `package.json`, so their CI skips the suite entirely and nothing downstream would ever have caught it. The tests are now denylisted from daftplate and travel with the skill in daftkit.
- `/diagram` now ships in the public `daftkit` export. It was held back from daftkit 1.0.0 alongside `/code-map` and `/deliberate`, which shell out to `$TEMPLATES/scripts/*.mjs` and would ship broken standalone — but `/diagram` is not in that position: it bundles its own `scan-structure.mjs` and `to-excalidraw.mjs` under the skill directory and names no `$TEMPLATES` path. The old exclusion was marked "daftplate-only until proven", and U1–U4 plus real-app acceptance is the proof. A new test walks every SKILL.md daftkit actually exports and fails if any of them names `$TEMPLATES`, so the standalone promise is now checked rather than reasoned about.

## [1.1.0] — 2026-07-24

The `/diagram` structure lens becomes a working board you can keep: it lays a repo
out as folders-and-cards you rearrange by hand, and `--update` merges a fresh
render back into the board you arranged instead of overwriting it.

### Added

- The `/diagram` structure lens now produces a **working board**: folders as nested Excalidraw frames, files as cards inside them (containment instead of a node graph, so nothing crosses). A new bundled scanner, `skills/diagram/scripts/scan-structure.mjs`, discovers files via `git ls-files --cached --others --exclude-standard` (tracked + untracked, `.gitignore` respected) with a walk fallback outside a repo, and applies a depth cap (default 3; deeper folders collapse to dashed summary cards) and a per-folder file cap (default 25; overflow collapses to one `(N files)` card). The board ships an annotation kit — a four-color status legend (done / in progress / error to fix / gap) and an empty "Gaps / To do" workbench frame. The flowchart, ER, and sequence renderers are unchanged; the imports-as-flowchart view remains reachable via the `described` lens. 15 new tests pin the scanner, the containment invariants (every framed element inside its frame, siblings never overlap), the legend/workbench, z-order, determinism, and the two CLIs end to end.
- The structure board is **semantic, not mechanical**: cards can carry a `label` plus a muted `detail` line (a folder of skills shows "orient — session-start working brief", not eleven identical `SKILL.md` cards), a folder that *is* a unit collapses to one card (`card: true`), and a top-level `relations` list renders as arrows **bound to the cards** — they stay attached while the board is rearranged; endpoints are root-relative paths or explicit ids, folders resolve to their frame. The skill now self-determines the organization (unit + one of five card presets + one of five relation modes, including a `focus` mode for "what does changing X affect") and confirms it with one four-option question — continue / second guess / state the intent / state intent and unit — before enriching the scanner's skeleton with grounded reads. 6 more tests (suite → 343).
- Relation arrows are **guaranteed legible within a folder**: cards that relations touch are laid out on a ring with an empty interior — the radius is closed-form (the chord skipping one neighbor must clear a card's half-diagonal, `r·(1−cos α)`), so no straight arrow between ring cards can pass through another card; related pairs are seated adjacent so most arrows are short hops, and unrelated cards keep the dense grid. Cross-folder arrows carry no guarantee (that would be real edge routing) — the skill says so and steers busy boards to the `notes` mode. 2 more tests, including a segment-vs-card sweep over a six-card ring with crossing chords (suite → 345).
- The board's layout follows the user's stable-zone rule (derived from their hand-reorganized reference board): cards without relations pack into the dense grid **above/left** so the user never needs to move them; connected cards take the open space below/right. A sparse, hub-shaped relation graph now lays out as **tiers** — targets top, sources below, rows centered so arrows run near-vertical lanes through the empty corridors between tiers (adjacent-tier and same-tier arrows are collision-free by construction; a tier-skipping arrow may cross a card, accepted because the board exists to be rearranged). Dense tangles (more intra-folder edges than cards) keep the ring and its hard guarantee. 3 more tests (suite → 348).
- The sparse layout matured into the **banded grid** (systematized from the user's second reference board): one global grid holds plain cards *and* connected sinks — cards that only receive lines join the same columns on their own bottom rows — and only line-originating cards drop into bands below, ranked by nearest target and **staggered on the half-grid** (odd bands half a pitch off-column, even bands back on-column — a brick lattice whose gaps are the arrow lanes; quarter-pitch is the documented manual escalation). On the reference model this regenerates the user's hand layout nearly coordinate-for-coordinate with zero arrows through cards (suite → 349).
- A `/deliberate` panel audit (three Codex archetypes, unanimous) hardened the board contract: relations are **normalized once** — endpoints resolved against the tree, unknown ones dropped before they can distort layout, self-links and duplicate edges removed — and that one set feeds connectedness, the mode pick, layout, arrows, and Mermaid; cycle members share a band (mutual-reachability grouping) instead of a traversal-order staircase; band depth clamps at 6; an `id` colliding with another entry's id or path throws instead of binding the wrong card; `status: done | in-progress | error | gap` is data with canonical legend colors (`color` overrides); the scanner warns on its non-git walk fallback; and the converter CLI **refuses to overwrite an existing board** without `--force` — the destructive-regeneration path is closed. Every generated element now carries a namespaced `customData.daftplate` ownership marker, the groundwork for update mode (`docs/designs/2026-07-24-diagram-board-update-mode.md` — merge instead of overwrite; shipped below). 8 more tests (suite → 357).
- The update-mode **gate checks ran against the real Excalidraw app** (headless excalidraw.com, real file-drop open path, trusted input): `customData` survives edit + save + reopen byte-identically — **update mode is unblocked** — and frame-in-frame `frameId` survives restore and persist. One caveat recorded: moving a parent frame collects one level of members (child frames and direct cards travel; a grandchild card did not, under keyboard move); mouse-drag behavior needs a ~30-second human check, downgraded from gate to UX note. Details in the plan doc's Gate section.
- The structure board is now **updatable, not just regenerable**: `to-excalidraw.mjs --update` merges a fresh render into the board the user has arranged instead of overwriting it (the old guard now points there, and `--force` still resets and beats `--update`). Matching is by the namespaced `customData.daftplate` marker every generated element carries — never by label text, so a renamed card is still the same card. Position, size, frame membership and background color are the user's and are kept, with a card's bound title and its grouped detail line riding the box; a label or detail that differs from the `lastGenerated` snapshot the generator stamps is a hand edit and survives, while text the user never touched refreshes. A unit new in the model lands in the **Gaps / To do** frame flagged `inbox: true` rather than being dropped into its folder; a unit gone from the model is never deleted but carried back in place, tinted (dashed, muted, `opacity 60`) and flagged `stale: true`, re-id'd so the old board and the fresh render cannot collide on `el-N`. Relation arrows are regenerated from the model and re-bound to the cards' final positions, and `frameId` is remapped by frame *identity* rather than copied raw — element ids are reassigned every render, so a carried id dangles. Anything the user drew themselves passes through verbatim. A board carrying no markers, or two elements claiming one marker, is **refused and left untouched**: the fresh render goes to `<out-base>.new.excalidraw` with the reason reported. `merge(rendered, existing)` is a pure, deterministic function of its two inputs. 17 tests in the new `tests/diagram-update.test.mjs` (suite → 374).
- Update mode was **accepted against the real Excalidraw app**, not only against its tests: a generated board was opened at excalidraw.com through the app's own file-drop path, reorganized with trusted input (two cards moved, a label retyped with the text tool, a card recolored from the app's own swatches, a note added by hand), then merged with a changed model and reopened. Every promise held — hand positions, the retyped label, the refreshed detail on an untouched card, the new unit in the Inbox, the dropped unit tinted stale, the user's note, both arrows re-bound. The run caught two defects the unit tests could not see. Two related cards dragged flush produced a **zero-length arrow, which Excalidraw silently discards on load** — the relation vanished from the board; `edgeSegment()` now falls back to the centre-to-centre segment (then to a stub) below a 2px minimum, in the renderer and the re-bind pass alike. And the legend's four palette cards, which are never matched individually and so always come from the fresh render, sat crooked after an update whenever the board grew a column: the re-anchor pass only fired for a card *outside* its frame, and a small shift stays inside the frame's slack — they now always re-seat against the preserved legend frame. Two behaviors are documented in the skill rather than changed: a status change does not repaint an existing card (a user recolor always wins), and a card nudged out of its frame with the arrow keys keeps its old `frameId` — Excalidraw only re-parents on drop — so the merge re-seats it. `SKILL.md` gains the update-mode flow (§3a), its preservation table, the refusal path, and the known edges. 2 more tests (suite → 376).
- A `/deliberate` panel refused to let update mode land, and was right: generated element ids were **positional** (`el-0, el-1, …` in emission order), so a unit that gained an earlier sibling was renumbered and a user's hand-drawn arrow bound to it did not dangle — it silently resolved to a *different* card. A board that looks valid and means something else is worse than a broken one. The merge now **preserves ids**: a matched element keeps the id it already carries in the user's board, and only genuinely new elements are given ids, never one that board already used. User elements are therefore never touched at all — bindings, `containerId`, `frameId` and whatever reference field Excalidraw adds next keep working without the merge knowing they exist — and the stale re-id (`el-stale-N`) disappears as a special case, so an arrow into a unit that left the model keeps pointing at the tinted card. `render()` is untouched and its ids stay positional and readable. Ownership tightened to match: an existing element is the generator's iff the render claimed its id or it carries a marker, so a caption the user bound to a card **survives** instead of being swept up as furniture; a card's `boundElements` is now the fresh render's list **unioned** with the user's entries, so an arrow's reciprocal side survives too. The merge **refuses** — and the CLI now exits non-zero, where a refusal previously read as a successful update — when a hand-drawn element references something the update cannot preserve (the legend's four identity-less swatches are the real case). Two behaviors change with it: a card is re-seated in its frame only when it has not moved since the board was last written (a `geom` snapshot separates the Excalidraw frame-drag desync from a move the user made, so an arrow-keyed move is no longer undone), and a status change now repaints a card still wearing its generated color while a color the user chose still wins. 8 tests in `tests/diagram-update.test.mjs` (27 in the file; suite → 384), the load-bearing one being the invariant that no id present in the existing board is ever assigned to a different element.

### Changed

- `REQUIRED_BASE_FILES` now includes the orient hook probe, so a base layer missing it fails `verify-templates.mjs`.
- `/new-project`'s §9 checklist no longer lists secret scanning and branch protection as "needs human". On a private repo on the free plan they are structurally unavailable, not merely undone, and the `secrets` CI job is the standing substitute.
- Branch protection now applies to admins (`enforce_admins=true`), so repo-standards §9.7's "even solo" holds. `--remote` prints the emergency unprotect command alongside it.

### Fixed

- `profiles/gas-webapp/profile.md` advertised `test: node --test tests/`, which runs nothing on Node 22+ — the positional argument is a glob pattern, not a directory walk — so every scaffolded gas-webapp repo named a test command that exits 1 against an empty match; it also named `verify: node scripts/local-verify.mjs`, a script the profile never ships, so the first command a fresh repo's `CLAUDE.md` runs exited `MODULE_NOT_FOUND`. Both are now `npm test`. `verify-templates.mjs` grew a `metaValueIssues` check that rejects all three ways a profile's metadata can break in the repo it produces: the `node --test <positional>` form, any value containing an unresolved `<TOKEN>` (which would survive `fillPlaceholders`' single substitution pass and fail the scaffold from a file that looks blameless), and a `scripts/<file>` reference the overlay does not ship.
- `code-map.mjs` ran `git rev-parse` with `shell: true`, so a repo path containing a space word-split and git exited 128. The map header then read `unknown`, silently voiding the staleness check the header itself instructs the reader to perform.
- `code-map.mjs` stamped the map with `HEAD`, but a map is generated and then committed, so the stamp was one commit behind the moment it landed and the freshness check the header prescribes reported every fresh map as stale. The stamp is now the last commit that touched an indexed file, which is stable across committing the map, docs-only commits, and a squash merge, while still moving when indexed source changes. `/orient` §1.3 and `/code-map` §4 follow.
- `code-map.mjs` indexed files git ignores, because `EXCLUDED_DIRS` is a fixed list that cannot know a repo's own ignores. A stale worktree copy under an ignored directory was indexed beside the real file, so every symbol grep returned two plausible anchors — 37% of one repo's index. Now filtered through `git ls-files --cached --others --exclude-standard`, which keeps untracked-but-not-ignored files so a freshly scaffolded repo still maps.
