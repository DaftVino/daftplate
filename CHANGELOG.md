## [1.5.0] — 2026-08-16

The standards pointer every scaffolded repo carries now resolves to something,
because something finally writes down where daftplate is. Publishing that fix
meant cloning the public export and running it for the first time in a while,
which is how this release also came to include the export not working at all.

### Added

- **Every scaffolded repo points at the standards through a path nothing had ever written down, and the checker that was supposed to notice verified twelve tools and not that one.** ADR 0001 makes `engineering-standards/repo-standards.md` canonical *here* and forbids copying it out, so each scaffolded CLAUDE.md carries a pointer at this checkout — resolved by a path no code recorded and no document named. Five repos in this workspace responded by vendoring a snapshot of the standards, which is the failure the pointer exists to prevent, and it is 13,019 bytes against a canonical 29,091. `install-skills.mjs` now writes the path into `~/.claude/CLAUDE.md` as a delimited block, `check-machine.mjs` reports whether it resolves and how stale it is, and `docs/setup-guide.md` states the step for the first time. **The refusals are the design.** An absent file is seeded from `claude-md-global.md` *gates and all* — a thin file carrying only the pointer passes every check while making the one thing ADR 0001:25 guarantees absent, so a checkout without that template refuses rather than creating one. An existing file missing the gates is **reported and never edited**: splicing template prose into a user-authored document writes content daftplate did not create, which is CLAUDE.md #5's spirit even though nothing is deleted. A marker span that cannot be bounded — duplicated, unclosed, orphaned or reordered — is refused rather than repaired, because a delimiter proves where a block claims to start, not who wrote what sits inside it. **Resolution means it IS daftplate, not that it looks like it.** The first version of that check accepted "is a git repo" plus "has repo-standards.md"; measured against this workspace, **all five repos holding the stale snapshot pass it**, so the checker would have certified the exact artifacts that caused the bug with a green tick. Identity is now `scripts/apply-layer.mjs` plus `profiles/` — the scaffolding engine, which no vendored copy has and which both ship in the public export — and deliberately not a remote allowlist, since the private build, the export and any fork all have different remotes and all are legitimately daftplate. **The staleness check never fetches**, because this command writes nothing anywhere: it compares against the last-fetched upstream and reports the fetch age beside it, worded as last-fetch-of-*any*-ref because `FETCH_HEAD` is rewritten by any fetch of any ref, and a repo that never fetched reports `null` rather than `0`. Every git call carries `-C <recorded path>`; without it the checker reports staleness for whatever repo the developer is standing in. The comparison target comes from `origin/HEAD`, never `@{u}` — that is the upstream of whatever branch the checkout was left on. **Three measurements changed the implementation.** `renameSync` on NTFS fails `EPERM` when any process holds the target open (an editor tab, antivirus mid-scan), so the atomic write retries three times and then refuses, never falling back to a plain write — that would reintroduce the torn write precisely when contention makes it likeliest, over the file holding the user's non-negotiable gates. `spawnSync` on a missing binary returns `status: null` with an error and **no exit code at all**, so `status > 0` and truthiness checks both fall through to a silent false-`current`. And `FETCH_HEAD` is **per-worktree**, so `rev-parse --git-path` resolves it into `.git/worktrees/<name>/` — which is why nothing may reach into `<path>/.git/` by construction, where `.git` is a file. **The mutation the plan wrote to catch that last one could not catch it**: the assertion was `notEqual(fetchAgeDays, undefined)`, which `null` satisfies, so the path-construction mutation passed a test written to kill it. Found by applying the mutation instead of trusting the test — issue #97's class, inside this plan's own guard against that class — and it now asserts a number. A missing, unresolvable or stale checkout is **advice and never an exit code**: it is a fact about another directory, not about whether this machine can build, and folding it into `ok` was applied as a mutation and watched kill the test that says so. `main()` also survives an export with no `skills/` (ADR 0002) rather than dying on an uncaught throw, because a public-export user is exactly the person who needs the path recorded, and it records the checkout that **contains the script** rather than `process.cwd()`, so running it from another repo no longer records that repo. 52 tests (suite 742 → 794).

- **CLAUDE.md's skill-routing table is now checked rather than trusted, and the check had to learn that most of the table is not this repo's.** The `## Skill routing` section names 21 skills and nothing asserted that any of them resolved — it was correct by hand-checking when written and by luck since. `tests/skill-routing.test.mjs` parses the section and requires every `/name` to resolve to `skills/<name>/SKILL.md` or to `skills/external-packs.json`, a committed allowlist that maps the intent name a session types to the installed directory name it lands on (`review` → `gstack-review`). **Sixteen of the 21 are gstack's**, so without the allowlist half the guard would have reported two-thirds of a working table as broken. The allowlist is **a declaration and deliberately not a probe**: nothing stats `~/.claude/skills/`, because a test that reads an installed tree passes or fails on which machine runs it, and CI has no such tree. The cost of that choice is stated in the file — an entry is an assertion by whoever adds it, and the same line that records a real dependency would also silence the guard for a skill nobody built. Three assertions exist to stop the allowlist becoming that: a name in it that CLAUDE.md no longer routes to is a failure, a route whose installed name does not carry its pack prefix is a failure (`"review": "review"` reads fine and resolves to nothing), and a name in it that also exists as a directory under `skills/` is a failure rather than a redundancy. **The pattern is the part most likely to be silently wrong.** The section is full of slashed prose — "Product ideas/brainstorming", "QA/testing", "Ship/deploy/PR", "spec/issue" — and a naive `/\/([a-z-]+)/` collects `brainstorming`, `testing`, `deploy` and `issue` as skills, so the match requires the slash to open a word and to not continue into a path; both remaining blind spots fail *open* and are named in a comment above it. **Renaming the heading was mutated and is why the empty-section assertion exists**: with the heading changed to `## Routing`, the resolution test itself goes green on zero names, which is the exact shape of a guard that stays green forever after a reformat. Four mutants were applied and watched red — an unresolvable entry (`does-not-exist`), a stale allowlist member, a mis-prefixed route, and the renamed heading — each dying on its own assertion and no other. 6 tests (suite 736 → 742).

### Fixed

- **The public export was not a working repo, and the CI that should have said so was structurally unable to.** Publishing the checkout work meant cloning the export and running it, which had not happened in a while: **41 tests failed**, and the worst of them was not a test. `scaffold.mjs:105` reads `package.json` to stamp the daftplate version into every scaffolded repo's `.daftplate.json` (ADR 0003), `package.json` was never allowlisted, and so **scaffolding — the export's entire purpose — threw `ENOENT` for anyone who cloned it**. The public CI could not report it: its test step is guarded by `if [ -f package.json ]`, so it printed "No package.json yet — nothing to test." over a suite of 478, which is how eleven recurrences of issue #54 went unseen. Shipping the file fixes both halves with one line and converts that guard from a permanent skip into a real run; it carries no dependencies (CLAUDE.md #4), no repository URL and no private names. Three test files leave the export because they cannot run in it — `deliberate.test.mjs` (reads `skills/` and `docs/records/`), `app-monolith-skills.test.mjs` (calls `installSkills(ROOT, …)`) and `skills.test.mjs`, which was already denylisted but still **tracked publicly**, because publish copies over the top and never deletes, so a denylist entry alone never removed it. **The remedy for #54 has been hand-written eleven times, so this adds two that are not hand-written.** `tests/publish.test.mjs` walks every shipped script and test for rooted reads of withheld paths; its exceptions are scoped per **file** rather than per path, because the first draft excused `skills` everywhere and thereby also excused the tests that genuinely break on it. A path that does not exist in this repo is skipped as a fixture destination rather than flagged, so `join(ROOT, 'nonexistent-install-target')` stays quiet. **Its blind spot is stated rather than left to be rediscovered**: it cannot see a withheld path read *inside* a function the file merely passes `ROOT` to, which is exactly how `app-monolith-skills.test.mjs` breaks. That class is covered by the second mechanism — `/publish` now builds the export and runs its suite before the sync PR, and a red suite blocks the publish. A fresh export runs **478 tests, 478 pass**, and the public CI ran them for the first time. `skills/external-packs.json` is also withheld from **daftkit**: it is not a skill but the allowlist this repo's routing test resolves against, daftkit ships no tests, and it would arrive as an orphan config describing another repo's routing — withheld rather than shipped-and-regretted, since publish never deletes and undoing costs a manual removal while adding it later costs one line. That test asserts the *shape* — anything directly under `skills/` that is not inside a skill directory — so the next config parked there is caught without another hand-written entry.

- **The public daftplate export ships a test that cannot run in it, and adding the guard above would have shipped a second.** The export withholds `skills/` (ADR 0002 — skills ship in daftkit) but carries `tests/`, and `tests/skills.test.mjs` calls `readdirSync` on `skills/` at module top level, so a stranger's clone throws `ENOENT: scandir skills` before one assertion runs. This is issue #54's class for the eighth time and the **first recurrence found already live** rather than caught on the way in; `tests/publish.test.mjs`'s guard cannot see it because that guard parses import specifiers and this is a `readdirSync`, the same blind spot that let the `.github/dependabot.yml` read through. Reproduced rather than reasoned about: an export-shaped tree holding `scripts/`, `CLAUDE.md` and the two test files fails both, on `scandir skills` and on `open skills/external-packs.json`. Both are added to `DAFTPLATE_CONFIG.denylist`; 30 test files still export.

- **The two shipped issue forms now ask for priority and for what closes the issue, and the label-driven design they were first specced as is impossible.** `base/files/dot-github/ISSUE_TEMPLATE/{bug-report,feature-request}.yml` gain a required `Priority` dropdown and a `What closes this` field naming a rung on the §6.6 evidence ladder plus the artifact that proves it. **The first design routed priority through `P1`–`P4` labels and does not work**: GitHub issue forms apply labels only through the static top-level `labels:` key, with no conditional path from a dropdown answer, and a label that does not already exist in the repo is silently ignored rather than created — so the scheme would have required creating four labels in every scaffolded repo, which is per-repo setup cost added by a change whose premise was reducing it. Linear closes the other half: its GitHub Issues Sync maps labels to **labels**, not to priority, so even a correctly applied `P1` would not have set the field it was named after. The dropdown therefore renders as body text feeding the human triage pass, which is where priority was always actually set. Its options use Linear's own words (Urgent/High/Medium/Low) so dressing is a copy rather than a translation, but **the templates never say "Linear"** — they ship to all eight profiles and Linear is this repo's own ADR 0006 deviation from §6.5, so the label reads "the board", which is true under either tracker. The evidence field is **required on feature requests and optional on bug reports**, because a bug report's existing "Expected behavior" already answers half of it while a feature request has no equivalent, and a required field that everyone fills with "n/a" is worse than no field: it looks like §6.6 is being met. The vestigial `# Place at .github/ISSUE_TEMPLATE/bug-report.yml` header is dropped — the `dot-` rule is CLAUDE.md #3, enforced by `apply-layer.mjs`, and this was the only statement of it that shipped downstream. This repo's own `.github/ISSUE_TEMPLATE/bug-report.yml`, a byte-identical mirror of the base copy, is updated with it; the equality that keeps them in step is pinned by the entry below.

- **The dot-github mirror is now pinned by a walk rather than by one hand-written test per pair, because the hand-written approach had already failed.** `base/files/dot-github/` ships five files and this repo dogfoods each as a live `.github/` counterpart, but only two of those pairs were pinned — `ci.yml` and `dependabot.yml`, one dedicated test each. The third and fourth were unpinned and the fifth **did not exist**: `ISSUE_TEMPLATE/feature-request.yml` shipped to every scaffolded repo while daftplate filed its own enhancement issues (#81-84) against no template at all, receiving neither the priority nor the evidence field the entry above adds. That gap is the argument against the list — a pair is pinned only if someone remembers to write its test, and for three of five nobody did. The new test **discovers** the tree with `walkFiles` and holds every file in it, so the next addition is covered the day it lands. **Repair direction is per-file rather than global**, which is why this could not be one uniform comparison: `INVERTED_REPAIR` exempts `ci.yml` and `dependabot.yml` from the content check because Dependabot can only bump the *live* copy, so their repair is live → template, and a uniform message would have advised the exact overwrite that silently reverts a reviewed security bump. They are still held to the **existence** half; only their content comparison lives in the older tests. Both failure modes were mutated and watched go red: removing the live mirror reports `missing: ['ISSUE_TEMPLATE/feature-request.yml']`, appending a line to the live PR template reports `drifted: ['PULL_REQUEST_TEMPLATE.md']`. `.github/ISSUE_TEMPLATE/feature-request.yml` is added, completing the mirror (suite 735 → 736).

## [1.4.0] — 2026-08-09

daft-cal piloted a Linear board (its ADR 0016), an evidence ladder, doc-size
budgets, and a vertical-slice execution model over three flushed outbox
issues; all four are now the canonical standard. Everything else in this
release accumulated on `main` since 1.3.0 without its own tag.

### Added

- **Six printable desk guides, and the generator that was specced for them was cut rather than built.** `desk-guides/` holds one self-contained HTML page each for Claude skills, Codex plugins, the coding workflow, the profile map, the release path, and where work lives — US Letter landscape, printed from the browser with Ctrl+P. `docs/designs/2026-07-28-printable-desk-guides.md` moves to **Superseded rather than deleted**, because the pages were written against it and it still owns their content model and, more importantly, the **type minimums that are the acceptance criteria** rather than a preference. The cost is stated on the pages' own README instead of discovered later: **they go stale silently**, nothing checks A1 against `~/.claude/skills` or C against `profiles/`, and that is precisely what the spec's "Alternatives considered" rejected hand-maintained cards to avoid. The four generator phases are filed as #81-84 so the work is deferred rather than lost. **The combined six-page bundle is deliberately absent**: each page's stylesheet diverged while being fitted to its own content — `.stop-band` means different things on B and D, and C and D tightened `.card` padding to clear measured overflow — so one merged document needs every page's CSS scoped under its own ancestor, i.e. a hand-maintained second copy of all six pages, which is the drift these pages already risk rather than a fix for it. **The bug worth carrying forward is not the one the spec guarded against.** The spec's render step blocks on "any overflow, clipped region, missing font"; a DOM `scrollHeight`/`scrollWidth` check duly reported CLEAN on a page B whose core-loop strip printed "Orient" as "Orien" and "worktree" as "worktre", because each cell carried an opaque background, `z-index: 1` and a negative margin and so painted over its neighbour's label. **Occlusion is a different failure from overflow** — the text is at full width, the box never scrolls, and the ink is gone anyway — and it was found by looking at the rendered page, not by the check that was supposed to catch it. Both assertions are now written into #82. A second measurement failure is recorded for the same reason: the first draft of page C was estimated at seven lines per card and written at twelve, and every one of its eight cards overflowed by 60-100px against a 145px box, which is the estimate-versus-measure gap the Phase 6 handoff already logged once.
- **`docs/records/<skill>/` resolves the `docs/panels` conflict, and resolves it wider than the conflict.** `/deliberate` wrote `docs/panels/`, `checkDocsSubdirs` allowed only `designs` and `adr`, and four records already existed — daftplate was breaking its own standard, unnoticed because `verify-repo.mjs` runs against scaffolded repos and never against daftplate. Neither resolution the spec suggested was taken. Records are now namespaced per skill under a universal `records/` bucket, so **the next skill that emits durable output needs no further standards change** — one edit, once, instead of one per skill. The semantics are **additive and that is the load-bearing part**: `checkDocsSubdirs(dir, extra)` unions `extra` onto `designs/adr/records` rather than being replaced by it, because all eight profiles restate "designs, adr" in their `docs-subdirs` and none restates "records", so a replacing implementation would flag `/deliberate`'s own output as a layout violation in every one of them. A test pins exactly that. The name was **not** `outbox`, which was the first proposal: `skills/standards-change/scripts/outbox.mjs` already owns `~/.daftplate/outbox/`, a transient queue that gets flushed and emptied, and reusing the word for a permanent in-repo archive would have put two opposite meanings on one term. Four records moved, `docs/panels/` is gone, and repo-standards §6.3 gains the rule plus the constraint that keeps it from becoming a second `docs/misc/`: a directory with no owning skill does not belong there (suite 730 → 731).

- **Template changes can now reach the repos daftplate already produced, and the mechanism refuses far more than it writes.** `/sync-standards` reads the `.daftplate.json` manifest ADR 0003 committed into every scaffolded repo and asks a pure `classify()` what may happen to each path. **Seven states, and the interesting ones are the refusals.** A file whose on-disk digest differs from the manifest is `MODIFIED` and left untouched **even when it happens to equal what the template would produce today** — convergence is not provenance, and silently adopting bytes daftplate cannot vouch for is the exact failure the manifest exists to prevent; the same reasoning gives `COLLISION` its twin case. `mode: 'overridden'` refuses only when today's candidate comes from `base`, i.e. the profile *dropped* its override, because a profile that still overrides should propagate normally. The `!prior` cases are evaluated first, and that ordering is load-bearing rather than cosmetic: the `OVERRIDDEN` gate reads `prior.mode`, so hoisting it throws a `TypeError` on precisely the newly-added-file case the feature exists to serve. A test pins it and the mutation was applied and watched turn five tests red. **`APPENDED` was designed, accepted twice, and then deleted** — by both Codex and a `/plan-eng-review` pass — on the reasoning that a whole-file digest cannot locate an appended segment. True, and beside the point: when the digest *matches*, the staged composition is the correct new whole file and no boundary is needed, so the gate was refusing a safe update; when it *differs*, `MODIFIED` already refuses, and the cause is that the manifest stores a hash rather than the original content. The real limit is narrow and now stated rather than discovered: **a developer-edited `.gitignore` cannot receive new template ignore rules**, while an unedited one syncs by whole-file rewrite. Candidate generation calls `scaffold()` itself rather than reimplementing its four steps, because drift between two implementations means every scaffolded `CLAUDE.md` reads as MODIFIED forever — `injectFragments` replaces three markers in that one file, and skipping the replay is the single most likely way this ships broken and useless. Its two side effects on the staging tree, a written manifest and a `verifyRepo` pass, are ignored deliberately and named in the source; extracting a side-effect-free `compose()` was rejected because it would reopen `scaffold.mjs`. **`.daftplate.json` is not extended**: recording the three profile command tokens was proposed and rejected, since candidate generation must read them from today's `profile.md`, so recorded copies could only ever cause skew — which is why 6a touches neither `scaffold.mjs` nor `buildProvenance()`, and `tests/scaffold.test.mjs` and `tests/provenance.test.mjs` are unmodified. Staging is `mkdtemp` under the OS temp root, removed in a `finally`, and `removeStaging()` refuses any path outside `tmpdir()` rather than trusting its only caller — a recursive delete is the one operation where being wrong is unrecoverable. `RETAINED` deliberately does not block the version advance: a path the template stopped producing is unresolvable by construction, since nothing here deletes, so counting it would pin the version forever. `--add` and `--restore` repeat and **there is no `--add-all`**, because naming each path is what makes adopting it a decision.
- **`/standards-change` gives a deliberate deviation somewhere to live that is not a comment nobody greps.** A note naming the rule and the reason queues to `~/.daftplate/outbox/`, and `--flush` turns one note into a daftplate ADR or a private GitHub issue. **Local rather than straight to GitHub** because daftplate publishes a curated public export (ADR 0004) and a note names a private repo and the standard it broke; an issue flush verifies the target is private before anything is searched or created. **Nothing is ever deleted** — a flush *moves* the note to `outbox/flushed/` byte-identical, and only after the ADR exists on disk or GitHub has returned a URL, so a failed flush leaves the note pending, which is the recoverable direction. There is no removal call anywhere in the module and a test asserts that against the source text. Every body carries `Outbox-ID: <uuid>` and creation searches for it first, so a retry after a partial failure is idempotent rather than filing the deviation twice. **The module imports only `node:*`, and that is a correctness requirement rather than a preference**: it installs into `~/.claude/skills/` and runs from repos with no daftplate checkout, so the `runCli` import a first draft used would have shipped a skill that throws on a missing module the first time anyone used it — the dangling-import class from issue #54 one layer earlier. A test parses the module's own import specifiers and asserts every one is a builtin. The path check is membership in the pending listing rather than string inspection, so `../secret.json` is refused before anything outside the outbox is read. **Issue #54 then fired for the seventh time anyway**, on the test file: the daftplate export ships `tests/` but not `skills/`, so `tests/standards-change.test.mjs` is denylisted, with a note that `tests/sync-standards.test.mjs` deliberately is not — it imports `scripts/sync-standards.mjs`, and `scripts/` ships. 62 tests (suite 659 → 721).

- **Pinned actions now have a refresh path, and two of the four things this session was specced to build were deleted instead.** H1a pinned every `uses:` to a commit SHA; a pin does not rot, but it does go unmaintained — a SHA predating a fixed `actions/checkout` bug carries that bug indefinitely with no signal. `base/files/dot-github/dependabot.yml` ships in the base layer and reaches every scaffolded repo, `.github/dependabot.yml` is this repo's own copy, and `files/dot-github/dependabot.yml` joins `REQUIRED_BASE_FILES`. **Majors are deliberately excluded from the group** (`update-types: ['minor', 'patch']`): a grouped major is a breaking change riding in on a PR titled like routine maintenance, reviewed at the attention routine maintenance gets, which is the failure the pinning exists to prevent. No auto-merge, for the same reason — the pin exists so a human reads the diff. §3.1's open question about private free-plan availability is closed by measurement: `gh api repos/…/automated-security-fixes` answers `{"enabled":false,"paused":false}` rather than 403, so the machinery is present and merely off.
- **The generation script (§9.2) was dropped, and the drift guard went back to being a test.** §9.2 resolved D5 by making `.github/workflows/ci.yml` generated from the base template, while also asserting that a Dependabot bump to the live file "propagates back" — two statements pointing opposite ways. They cannot both hold: Dependabot only scans `.github/workflows/`, so it can only ever touch the live copy, and re-running a template→live generator afterwards **silently reverts a reviewed security bump**. Inverting the generator to live→template would work but buys nothing a comparison does not, for two 57-line files with no transformation between them. So D5 is a test again, with the repair direction (live→template, never the reverse) stated in the assertion message rather than left to be inferred. The accepted consequence, which is stated here because it will look like a bug otherwise: **every Dependabot PR in this repo arrives red.** It bumps the live file, the equality test fails, and `test` is a required check under `enforce_admins`, so a human must push the template copy onto the bot's branch before it can merge. That is the forcing function, not a defect.
- **The gitleaks staleness check (§9.5) was dropped because H1a's own lint forbids it** — proven by running it, not argued. A `curl` to the releases API trips `workflow-unverified-download`, because that rule encodes "every download needs a committed digest" and an API query is the first thing in this corpus to falsify the assumption. Routing around it with `gh api` or Node's `fetch` would evade the guard rather than resolve it, four hours after shipping it. The second consideration is that the check can report that 8.30.1 is stale but cannot establish a trusted digest for the replacement — fetching that from the same release is exactly what D3 refuses — so the human work is unchanged and only the nagging is new. **Recorded rather than settled:** an adversarial pass argued the reverse, that staleness detection and digest authentication are separate problems and the notification still has value. The falsifier is a real one; it is written down so reopening it costs a decision rather than a rediscovery.
- **The export allowlist decision was made, reversed on evidence, and the reversal is the interesting half.** §9.6 handed this session a choice: widen `DAFTPLATE_CONFIG.allowlist` by `.github/dependabot.yml`, or accept the gap and say why. It was first decided as *accept*, on the reasoning that `publish.mjs` copies over the top and never deletes, so a Dependabot PR merged on the public mirror is destroyed by the next sync — bump automation where changes cannot durably land. That reasoning is correct and was beside the point. **The export ships `tests/`, and `tests/verify-templates.test.mjs` reads `.github/dependabot.yml` directly**, so withholding it hands a stranger a clone whose own test suite throws `ENOENT`. An export whose tests reference a file it withholds is broken regardless of what one thinks about mirrors. This is the dangling-import defect one class over — a *read* rather than an *import* — and `tests/publish.test.mjs`'s guard cannot see it, because it parses import specifiers only. Logged on #54, whose argument is precisely that this remedy keeps being hand-written.
- **Four of the new tests exist because a mutation would otherwise pass.** The Dependabot assertion is indentation-scoped to one `updates:` entry rather than three regexes over the file, because a config whose `github-actions` entry has *no schedule at all* passes "contains github-actions" and "contains `interval: weekly`" as long as some other entry supplies the second — that exact mutation is now its own test. The scaffold-delivery assertion covers all eight profiles, because `REQUIRED_BASE_FILES` is checked against the template tree and never against a scaffold: dropping the file in `apply-layer.mjs`'s `collect()` left every other H1b test green while no repo received the config. That mutation was applied and watched turning all eight red, then reverted. `docs/architecture.md` also stopped claiming a base-file count, having drifted two entries behind the array before this change touched it. 15 tests (suite 644 → 659).

### Security

- **The CI template trusted a mutable tag and executed a tarball nobody checked, and it ships into every repo scaffolded from this one.** `base/files/dot-github/workflows/ci.yml` pulled `actions/checkout@v4` and `actions/setup-node@v4` — tags, which the action's owner or anyone who compromises them can repoint at different code after the pin was reviewed — and installed gitleaks by piping a `curl` straight into `tar`, with `fetch-depth: 0`, meaning arbitrary downloaded bytes ran against the full history of every repo. Every `uses:` across all four workflow files (the base template, this repo's live `ci.yml`, `vault.yml` and `library.yml`) is now pinned to a 40-character commit SHA with a trailing `# vX.Y.Z`, and the gitleaks install is a download-verify-extract sequence under `set -euo pipefail` with the digest checked before `tar` touches the bytes. **Each SHA was resolved once and reused across all four files**, because nothing here runs `vault.yml` or `library.yml` — a transposed character in a profile workflow would surface in a downstream scaffold, not in this repo's CI, so per-file transcription is the one thing this change could not afford. Resolved live rather than carried from the spec, which deliberately holds no literals: `actions/checkout` v4.4.0 → `11d5960a326750d5838078e36cf38b85af677262`, `actions/setup-node` v4.4.0 → `49933ea5288caeca8642d1e84afbd3f7d6820020`, both **byte-identical to what the moving `@v4` tag resolves to today**, so the pin is a zero-behaviour-change hardening rather than an upgrade smuggled in beside one. The gitleaks 8.30.1 `linux_x64` digest `551f6fc8…70eb` came from the release's checksums file and was then confirmed against the real tarball with a local `sha256sum -c`. It is a **committed literal and not a runtime fetch**, on purpose: pulling `gitleaks_<v>_checksums.txt` from the same release, over the same channel, at the same moment as the artifact verifies nothing, because whoever can alter the tarball can alter the checksums beside it. The one thing no local check can prove is that the pinned digest matches what a real runner downloads — only this PR's own green CI does, which is why it is the acceptance step rather than a unit test.

Verified safe before being applied rather than after — all four jobs are read-only (`npm test`, `gitleaks git .`, and the two `node` validators), and job-level `permissions` does not constrain jobs added later, so the cross-profile blast radius the original scope-out worried about does not arise.

The last one is where the review changed the design: requiring that `sha256sum -c` merely *appear* in the block would pass a workflow doing exactly what the digest reasoning above forbids, so the rule instead requires the block to reference a workflow `env:` key whose value is **64 lowercase hex**, and a test pins that precise refused pattern — `curl` the artifact, `curl` the checksums beside it, `sha256sum -c` — as a violation. ### Added

Token forecasting is out; reporting the real cost afterwards stays. The **executor is now an explicit choice** — codex for independence, subagents when the panel must inspect an artifact that cannot be pasted — decided on artifact access, provenance and independence and **never on line count**, with the independence surrendered named in the cost report. Substituting the archetypes is allowed but must preserve *opposed claims tied to acceptance criteria* with one seat defending the status quo on the merits; a nominal "restraint" seat is called out as performative. `buildPrompt`'s terse format is mandated over any invented multi-section schema, which homogenises three traditions into three near-identical documents, and the skill states the principle so it survives the helper rotting. The closing `AskUserQuestion` narrows to **one question at approval altitude** — the run asked four where one was open — while keeping the rule that the panel advises and the owner decides. 2 more tests (suite → 388).

## [1.1.0] — 2026-07-24

The `/diagram` structure lens becomes a working board you can keep: it lays a repo
out as folders-and-cards you rearrange by hand, and `--update` merges a fresh
render back into the board you arranged instead of overwriting it.

### Added

- The `/diagram` structure lens now produces a **working board**: folders as nested Excalidraw frames, files as cards inside them (containment instead of a node graph, so nothing crosses). A new bundled scanner, `skills/diagram/scripts/scan-structure.mjs`, discovers files via `git ls-files --cached --others --exclude-standard` (tracked + untracked, `.gitignore` respected) with a walk fallback outside a repo, and applies a depth cap (default 3; deeper folders collapse to dashed summary cards) and a per-folder file cap (default 25; overflow collapses to one `(N files)` card). The board ships an annotation kit — a four-color status legend (done / in progress / error to fix / gap) and an empty "Gaps / To do" workbench frame. The flowchart, ER, and sequence renderers are unchanged; the imports-as-flowchart view remains reachable via the `described` lens. 15 new tests pin the scanner, the containment invariants (every framed element inside its frame, siblings never overlap), the legend/workbench, z-order, determinism, and the two CLIs end to end.
- The structure board is **semantic, not mechanical**: cards can carry a `label` plus a muted `detail` line (a folder of skills shows "orient — session-start working brief", not eleven identical `SKILL.md` cards), a folder that *is* a unit collapses to one card (`card: true`), and a top-level `relations` list renders as arrows **bound to the cards** — they stay attached while the board is rearranged; endpoints are root-relative paths or explicit ids, folders resolve to their frame. The skill now self-determines the organization (unit + one of five card presets + one of five relation modes, including a `focus` mode for "what does changing X affect") and confirms it with one four-option question — continue / second guess / state the intent / state intent and unit — before enriching the scanner's skeleton with grounded reads. 6 more tests (suite → 343).
- Relation arrows are **guaranteed legible within a folder**: cards that relations touch are laid out on a ring with an empty interior — the radius is closed-form (the chord skipping one neighbor must clear a card's half-diagonal, `r·(1−cos α)`), so no straight arrow between ring cards can pass through another card; related pairs are seated adjacent so most arrows are short hops, and unrelated cards keep the dense grid. Cross-folder arrows carry no guarantee (that would be real edge routing) — the skill says so and steers busy boards to the `notes` mode. 2 more tests, including a segment-vs-card sweep over a six-card ring with crossing chords (suite → 345).
- The board's layout follows the user's stable-zone rule (derived from their hand-reorganized reference board): cards without relations pack into the dense grid **above/left** so the user never needs to move them; connected cards take the open space below/right. A sparse, hub-shaped relation graph now lays out as **tiers** — targets top, sources below, rows centered so arrows run near-vertical lanes through the empty corridors between tiers (adjacent-tier and same-tier arrows are collision-free by construction; a tier-skipping arrow may cross a card, accepted because the board exists to be rearranged). Dense tangles (more intra-folder edges than cards) keep the ring and its hard guarantee. 3 more tests (suite → 348).
- The sparse layout matured into the **banded grid** (systematized from the user's second reference board): one global grid holds plain cards *and* connected sinks — cards that only receive lines join the same columns on their own bottom rows — and only line-originating cards drop into bands below, ranked by nearest target and **staggered on the half-grid** (odd bands half a pitch off-column, even bands back on-column — a brick lattice whose gaps are the arrow lanes; quarter-pitch is the documented manual escalation). On the reference model this regenerates the user's hand layout nearly coordinate-for-coordinate with zero arrows through cards (suite → 349).
- A `/deliberate` panel audit (three Codex archetypes, unanimous) hardened the board contract: relations are **normalized once** — endpoints resolved against the tree, unknown ones dropped before they can distort layout, self-links and duplicate edges removed — and that one set feeds connectedness, the mode pick, layout, arrows, and Mermaid; cycle members share a band (mutual-reachability grouping) instead of a traversal-order staircase; band depth clamps at 6; an `id` colliding with another entry's id or path throws instead of binding the wrong card; `status: done | in-progress | error | gap` is data with canonical legend colors (`color` overrides); the scanner warns on its non-git walk fallback; and the converter CLI **refuses to overwrite an existing board** without `--force` — the destructive-regeneration path is closed. Every generated element now carries a namespaced `customData.daftplate` ownership marker, the groundwork for update mode (`docs/designs/2026-07-24-diagram-board-update-mode.md` — merge instead of overwrite; shipped below). 8 more tests (suite → 357).
- The update-mode **gate checks ran against the real Excalidraw app** (headless excalidraw.com, real file-drop open path, trusted input): `customData` survives edit + save + reopen byte-identically — **update mode is unblocked** — and frame-in-frame `frameId` survives restore and persist. One caveat recorded: moving a parent frame collects one level of members (child frames and direct cards travel; a grandchild card did not, under keyboard move); mouse-drag behavior needs a ~30-second human check, downgraded from gate to UX note. Details in the plan doc's Gate section.
- The structure board is now **updatable, not just regenerable**: `to-excalidraw.mjs --update` merges a fresh render into the board the user has arranged instead of overwriting it (the old guard now points there, and `--force` still resets and beats `--update`). Matching is by the namespaced `customData.daftplate` marker every generated element carries — never by label text, so a renamed card is still the same card. Position, size, frame membership and background color are the user's and are kept, with a card's bound title and its grouped detail line riding the box; a label or detail that differs from the `lastGenerated` snapshot the generator stamps is a hand edit and survives, while text the user never touched refreshes. A unit new in the model lands in the **Gaps / To do** frame flagged `inbox: true` rather than being dropped into its folder; a unit gone from the model is never deleted but carried back in place, tinted (dashed, muted, `opacity 60`) and flagged `stale: true`, re-id'd so the old board and the fresh render cannot collide on `el-N`. Relation arrows are regenerated from the model and re-bound to the cards' final positions, and `frameId` is remapped by frame *identity* rather than copied raw — element ids are reassigned every render, so a carried id dangles. Anything the user drew themselves passes through verbatim. A board carrying no markers, or two elements claiming one marker, is **refused and left untouched**: the fresh render goes to `<out-base>.new.excalidraw` with the reason reported. `merge(rendered, existing)` is a pure, deterministic function of its two inputs. 17 tests in the new `tests/diagram-update.test.mjs` (suite → 374).
- Update mode was **accepted against the real Excalidraw app**, not only against its tests: a generated board was opened at excalidraw.com through the app's own file-drop path, reorganized with trusted input (two cards moved, a label retyped with the text tool, a card recolored from the app's own swatches, a note added by hand), then merged with a changed model and reopened. Every promise held — hand positions, the retyped label, the refreshed detail on an untouched card, the new unit in the Inbox, the dropped unit tinted stale, the user's note, both arrows re-bound. The run caught two defects the unit tests could not see. Two related cards dragged flush produced a **zero-length arrow, which Excalidraw silently discards on load** — the relation vanished from the board; `edgeSegment()` now falls back to the centre-to-centre segment (then to a stub) below a 2px minimum, in the renderer and the re-bind pass alike. And the legend's four palette cards, which are never matched individually and so always come from the fresh render, sat crooked after an update whenever the board grew a column: the re-anchor pass only fired for a card *outside* its frame, and a small shift stays inside the frame's slack — they now always re-seat against the preserved legend frame. Two behaviors are documented in the skill rather than changed: a status change does not repaint an existing card (a user recolor always wins), and a card nudged out of its frame with the arrow keys keeps its old `frameId` — Excalidraw only re-parents on drop — so the merge re-seats it. `SKILL.md` gains the update-mode flow (§3a), its preservation table, the refusal path, and the known edges. 2 more tests (suite → 376).
- A `/deliberate` panel refused to let update mode land, and was right: generated element ids were **positional** (`el-0, el-1, …` in emission order), so a unit that gained an earlier sibling was renumbered and a user's hand-drawn arrow bound to it did not dangle — it silently resolved to a *different* card. A board that looks valid and means something else is worse than a broken one. The merge now **preserves ids**: a matched element keeps the id it already carries in the user's board, and only genuinely new elements are given ids, never one that board already used. User elements are therefore never touched at all — bindings, `containerId`, `frameId` and whatever reference field Excalidraw adds next keep working without the merge knowing they exist — and the stale re-id (`el-stale-N`) disappears as a special case, so an arrow into a unit that left the model keeps pointing at the tinted card. `render()` is untouched and its ids stay positional and readable. Ownership tightened to match: an existing element is the generator's iff the render claimed its id or it carries a marker, so a caption the user bound to a card **survives** instead of being swept up as furniture; a card's `boundElements` is now the fresh render's list **unioned** with the user's entries, so an arrow's reciprocal side survives too. The merge **refuses** — and the CLI now exits non-zero, where a refusal previously read as a successful update — when a hand-drawn element references something the update cannot preserve (the legend's four identity-less swatches are the real case). Two behaviors change with it: a card is re-seated in its frame only when it has not moved since the board was last written (a `geom` snapshot separates the Excalidraw frame-drag desync from a move the user made, so an arrow-keyed move is no longer undone), and a status change now repaints a card still wearing its generated color while a color the user chose still wins. 8 tests in `tests/diagram-update.test.mjs` (27 in the file; suite → 384), the load-bearing one being the invariant that no id present in the existing board is ever assigned to a different element.
