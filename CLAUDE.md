# CLAUDE.md

## Project

`daftplate` is the source of truth for repo scaffolding and engineering standards. It produces other repos; it is not an application.

This repository is a **one-directional public export**. It is generated from a private working repository and copied over the top on each sync, so changes made here are overwritten rather than merged. Treat it as a published artifact: read it, clone it, scaffold from it — but land changes upstream, not here.

## Repo-specific constraints

1. **Standards are never vendored.** New repos get a CLAUDE.md pointer plus `base/files/docs/quick-ref-workflow.md`. Anything that copies `engineering-standards/` into another repo is a bug.
2. **Layers only differ.** `profiles/<type>/files/` adds; `profiles/<type>/files-override/` replaces a base file, and the profile descriptor beside them must say why. A silent collision is a hard error (`apply-layer --strict`).
3. **Dotfile templates are stored `dot-`-prefixed** (`dot-gitignore` → `.gitignore` on copy) so template files never take effect inside this repo. `scripts/apply-layer.mjs` owns that rule.
4. **Scripts stay dependency-free.** `package.json` has no `dependencies` or `devDependencies`; tests use the built-in `node:test` runner.
5. **Nothing deletes what it did not create.** No `rmSync` against a user directory, ever.
6. **Every implementation plan is phased**, each phase executable in a fresh session within ~150k tokens, with a files-to-read manifest per phase.

## What this export does not carry

Named so a reader knows the absence is deliberate rather than an omission.

- **The agent skills.** They are published separately as `daftkit`, which is a plugin rather than a directory of loose skills. The routing table that selects between them lives with them.
- **The decision records and active plans.** `docs/decision-log.md` carries the decisions themselves, written for a reader outside the workspace; the underlying records and design documents stay private.
- **The publishing tool and its tests.** The export is generated by a script that holds the private-name list, so it is private tooling by construction.
- **The issue-tracking workflow.** Issues are tracked on a private board. Nothing in this repository depends on it.
